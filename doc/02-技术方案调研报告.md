## 一、技术栈选型调研

### 1.1 跨平台UI框架对比

#### 方案A: Flutter

**优势**:
- ✅ 单一代码库支持桌面（Win/Mac/Linux）+ 移动端（iOS/Android）
- ✅ 原生性能，60fps流畅动画
- ✅ 丰富的UI组件库和动画系统
- ✅ Dart语言学习曲线平缓
- ✅ 热重载提升开发效率
- ✅ 包体积相对较小（15-30MB）

**劣势**:
- ⚠️ 桌面端生态相对不成熟（稳定版2021年才发布）
- ⚠️ 系统级API调用需要通过Platform Channel
- ⚠️ 窗口管理能力有限（需要第三方插件如window_manager）
- ⚠️ 内存占用比原生高（但比Electron低）

**适用场景**: 需要统一桌面+移动端代码库，注重性能和包体积

**技术栈**:
```yaml
dependencies:
  flutter: sdk: flutter
  window_manager: ^0.3.0
  tray_manager: ^0.2.0
  local_notifier: ^0.1.0
  path_provider: ^2.1.0
  sqflite: ^2.3.0
  hive: ^2.2.0
```

---

#### 方案B: Tauri (桌面) + Flutter (移动)

**优势**:
- ✅ Tauri包体积极小（<5MB）
- ✅ 内存占用低（使用系统WebView）
- ✅ Rust后端性能优秀，安全性高
- ✅ 前端可用任意Web技术栈（React/Vue/Svelte）
- ✅ 系统API调用方便（Rust直接调用）
- ✅ 绿色软件特性好

**劣势**:
- ⚠️ 需要维护两套代码（桌面Web + 移动Flutter）
- ⚠️ Rust学习曲线陡峭
- ⚠️ WebView渲染性能不如原生（但对桌面宠物足够）
- ⚠️ 不同系统WebView版本差异可能导致兼容性问题

**适用场景**: 桌面端优先，追求极致轻量，团队有Rust经验

**技术栈**:
```toml
[dependencies]
tauri = "2.0"
serde = { version = "1.0", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
```

---

#### 方案C: Electron

**优势**:
- ✅ 生态最成熟，社区资源丰富
- ✅ 前端技术栈熟悉度高
- ✅ 调试工具完善（Chrome DevTools）
- ✅ 跨平台兼容性最好

**劣势**:
- ❌ 包体积巨大（100MB+）
- ❌ 内存占用高（200MB+）
- ❌ 启动速度慢
- ❌ 不符合"绿色软件"要求

**结论**: **不推荐**，违背项目"少依赖、轻量级"原则

---

### 1.2 推荐方案

**首选: Flutter全栈**

**理由**:
1. 单一代码库降低维护成本
2. 性能满足需求（桌面宠物不需要极致性能）
3. 开发效率高，适合小团队
4. 移动端支持完善

**备选: Tauri + Flutter**

**理由**:
1. 如果桌面端性能/包体积要求极高
2. 团队有Rust经验
3. 可接受维护两套代码的成本

## 二、P2P网络方案调研

### 2.1 方案对比

#### 方案A: libp2p

**技术特点**:
- 去中心化DHT（Kademlia）
- 支持多种传输协议（TCP/UDP/QUIC/WebSocket）
- 内置NAT穿透（AutoNAT + Hole Punching）
- 支持中继（Circuit Relay）

**优势**:
- ✅ 完全去中心化，无需中心服务器
- ✅ IPFS同款技术，成熟稳定
- ✅ 支持多种传输协议
- ✅ 社区活跃

**劣势**:
- ⚠️ 学习曲线陡峭
- ⚠️ Dart版本（libp2p_dart）不成熟
- ⚠️ 需要自建Bootstrap节点

---

#### 方案B: WebRTC

**技术特点**:
- 浏览器原生支持
- STUN/TURN服务器辅助NAT穿透
- 支持音视频流（本项目用不到）

**优势**:
- ✅ Flutter有成熟插件（flutter_webrtc）
- ✅ 文档丰富，易于上手
- ✅ NAT穿透成功率高
- ✅ 可使用公共STUN服务器（Google/Cloudflare）

**劣势**:
- ⚠️ 需要信令服务器（Signaling Server）
- ⚠️ 严格NAT环境需要TURN服务器（有成本）

**Flutter集成**:
```yaml
dependencies:
  flutter_webrtc: ^0.11.0
  socket_io_client: ^2.0.0
```

**架构**:
```
客户端A <---> 信令服务器 <---> 客户端B
    |                              |
    +-------- WebRTC P2P ----------+
```

---

### 2.2 推荐方案

**首选: WebRTC**

**理由**:
1. Flutter生态成熟
2. 开发效率高
3. NAT穿透成功率高
4. 可使用免费STUN服务器

**技术架构**:
```
组件:
1. 信令服务器（Node.js + Socket.IO）
2. STUN服务器（使用公共服务或自建coturn）
3. TURN服务器（可选，严格NAT环境fallback）

连接流程:
1. 客户端A向信令服务器注册
2. 客户端B请求连接A
3. 信令服务器转发SDP/ICE信息
4. WebRTC建立P2P连接
5. 如果P2P失败，通过TURN中继
```

**成本估算**:
- 信令服务器: 1核2G云服务器，¥300/年
- STUN服务器: 使用Google免费服务
- TURN服务器: 按需开启，¥500/年（1000用户以内）

```dart
class AICache {
  Map<String, String> cache = {};

    String key = md5(prompt);
    if (cache.containsKey(key)) {
      return cache[key]!;
    }
    String response = await callAI(prompt);
    cache[key] = response;
    return response;
  }
}
```

```dart
class RateLimiter {

    bool isPremium = checkPremiumStatus(userId);
    return todayCount < (isPremium ? premiumUserLimit : freeUserLimit);
  }
}
```

- ✅ 数据迁移方便

- ✅ 性能优秀

## 五、系统权限管理方案

### 5.1 权限分级

**Level 0: 无需确认**
- 读取宠物自身状态
- 显示通知
- 播放音效

**Level 1: 首次确认**
- 读取桌面文件列表
- 读取系统信息
- 访问剪贴板

**Level 2: 每次确认**
- 创建/删除文件
- 修改文件内容
- 执行系统命令
- 安装软件

**Level 3: 明确授权**
- 访问敏感目录（Documents/Downloads）
- 网络请求
- 摄像头/麦克风

### 5.2 权限确认UI


### 7.2 配置文件位置

**优先级**:
1. `./data/config/` (便携模式)
2. `~/.cyber-pet/` (用户目录)
3. `/etc/cyber-pet/` (系统目录，仅Linux)

**检测逻辑**:
```dart
String getConfigPath() {
  String portableConfig = path.join(
    path.dirname(Platform.resolvedExecutable),
    'data',
    'config',
  );
  if (Directory(portableConfig).existsSync()) {
    return portableConfig;
  }
  
  return path.join(
    Platform.environment['HOME'] ?? Platform.environment['USERPROFILE']!,
    '.cyber-pet',
  );
}
```

### 7.3 卸载清理

**Windows注册表**: 不写入
**macOS启动项**: 不自动添加
**Linux服务**: 不创建systemd服务

**卸载方式**: 直接删除程序目录即可
