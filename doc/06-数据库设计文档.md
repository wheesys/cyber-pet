## 三、表结构设计

### 3.1 宠物表（pets）

**用途**：存储宠物基础信息

```sql
CREATE TABLE pets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    type TEXT NOT NULL,
    personality TEXT NOT NULL,
    avatar_path TEXT,
    level INTEGER DEFAULT 1,
    experience INTEGER DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_active INTEGER DEFAULT 1,
    
    CHECK (level >= 1 AND level <= 100),
    CHECK (experience >= 0),
    CHECK (is_active IN (0, 1))
);
```

**字段说明**：
- `id`: 主键，自增
- `name`: 宠物名称，最长50字符
- `type`: 宠物类型（cat=猫, dog=狗, rabbit=兔子, custom=自定义）
- `personality`: 性格模板（playful=古灵精怪, calm=沉稳, smart=聪明, shy=文静）
- `avatar_path`: 形象资源路径
- `level`: 等级（1-100）
- `experience`: 经验值
- `created_at`: 创建时间（YYYY-MM-DD HH:MM:SS）
- `updated_at`: 更新时间（YYYY-MM-DD HH:MM:SS）
- `is_active`: 是否激活（0=已删除, 1=正常）

**索引**：
```sql
CREATE INDEX idx_pets_is_active ON pets(is_active);
CREATE INDEX idx_pets_created_at ON pets(created_at DESC);
CREATE INDEX idx_pets_type ON pets(type);
```

**示例数据**：
```sql
INSERT INTO pets (name, type, personality, avatar_path) VALUES
('小白', 'cat', 'playful', '/assets/pets/cat_white.png'),
('旺财', 'dog', 'calm', '/assets/pets/dog_brown.png');
```

### 3.2 宠物状态表（pet_states）

**用途**：存储宠物实时状态

```sql
CREATE TABLE pet_states (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    pet_id INTEGER NOT NULL,
    mood INTEGER DEFAULT 50,
    energy INTEGER DEFAULT 100,
    position_x REAL DEFAULT 0,
    position_y REAL DEFAULT 0,
    current_action TEXT DEFAULT 'idle',
    last_active DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (pet_id) REFERENCES pets(id) ON DELETE CASCADE,
    CHECK (mood >= 0 AND mood <= 100),
    CHECK (energy >= 0 AND energy <= 100)
);
```

**字段说明**：
- `pet_id`: 关联宠物ID
- `mood`: 心情值（0-100）
- `energy`: 能量值（0-100）
- `position_x`: X坐标（屏幕像素）
- `position_y`: Y坐标（屏幕像素）
- `current_action`: 当前动作（idle/walk/run/sit/sleep）
- `last_active`: 最后活跃时间
- `updated_at`: 更新时间

**索引**：
```sql
CREATE UNIQUE INDEX idx_pet_states_pet_id ON pet_states(pet_id);
CREATE INDEX idx_pet_states_last_active ON pet_states(last_active DESC);
```

### 3.3 互动记录表（interactions）

**用途**：记录用户与宠物的互动历史

```sql
CREATE TABLE interactions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    pet_id INTEGER NOT NULL,
    interaction_type TEXT NOT NULL,
    content TEXT,
    metadata TEXT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (pet_id) REFERENCES pets(id) ON DELETE CASCADE
);
```

**字段说明**：
- `pet_id`: 关联宠物ID
- `interaction_type`: 互动类型（chat=对话, feed=喂食, play=玩耍, file_op=文件操作）
- `content`: 互动内容（对话内容、操作描述等）
- `metadata`: 元数据（JSON格式，存储额外信息）
- `created_at`: 创建时间

**索引**：
```sql
CREATE INDEX idx_interactions_pet_id ON interactions(pet_id);
CREATE INDEX idx_interactions_created_at ON interactions(created_at DESC);
CREATE INDEX idx_interactions_type ON interactions(interaction_type);
CREATE INDEX idx_interactions_pet_time ON interactions(pet_id, created_at DESC);
```

**metadata示例**：
```json
{
  "ai_model": "deepseek-v4-pro",
  "response_time": 1234,
  "tokens_used": 150
}
```

### 3.4 P2P连接记录表（p2p_connections）

**用途**：记录跨设备P2P连接历史

```sql
CREATE TABLE p2p_connections (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    local_pet_id INTEGER NOT NULL,
    remote_peer_id TEXT NOT NULL,
    remote_pet_name TEXT,
    connection_type TEXT NOT NULL,
    duration INTEGER,
    data_transferred INTEGER DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    disconnected_at DATETIME,
    
    FOREIGN KEY (local_pet_id) REFERENCES pets(id) ON DELETE CASCADE,
    CHECK (connection_type IN ('direct', 'relay', 'user_relay'))
);
```

**字段说明**：
- `local_pet_id`: 本地宠物ID
- `remote_peer_id`: 远程节点ID（libp2p PeerId）
- `remote_pet_name`: 远程宠物名称
- `connection_type`: 连接类型（direct=直连, relay=固定中继, user_relay=用户中继）
- `duration`: 连接时长（秒）
- `data_transferred`: 传输数据量（字节）
- `created_at`: 连接时间
- `disconnected_at`: 断开时间

**索引**：
```sql
CREATE INDEX idx_p2p_local_pet ON p2p_connections(local_pet_id);
CREATE INDEX idx_p2p_created_at ON p2p_connections(created_at DESC);
CREATE INDEX idx_p2p_remote_peer ON p2p_connections(remote_peer_id);
```

### 3.5 文件操作日志表（file_operations）

**用途**：记录宠物执行的文件操作，用于审计

```sql
CREATE TABLE file_operations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    pet_id INTEGER NOT NULL,
    operation_type TEXT NOT NULL,
    file_path TEXT NOT NULL,
    status TEXT NOT NULL,
    error_message TEXT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (pet_id) REFERENCES pets(id) ON DELETE CASCADE,
    CHECK (operation_type IN ('read', 'write', 'delete', 'move', 'copy')),
    CHECK (status IN ('pending', 'success', 'failed', 'cancelled'))
);
```

**字段说明**：
- `pet_id`: 执行操作的宠物ID
- `operation_type`: 操作类型（read/write/delete/move/copy）
- `file_path`: 文件路径
- `status`: 状态（pending=待执行, success=成功, failed=失败, cancelled=取消）
- `error_message`: 错误信息
- `created_at`: 创建时间

**索引**：
```sql
CREATE INDEX idx_file_ops_pet_id ON file_operations(pet_id);
CREATE INDEX idx_file_ops_created_at ON file_operations(created_at DESC);
CREATE INDEX idx_file_ops_status ON file_operations(status);
```

### 3.6 礼物记录表（gifts）

**用途**：记录宠物跨设备互动时带回的礼物

```sql
CREATE TABLE gifts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    pet_id INTEGER NOT NULL,
    from_peer_id TEXT NOT NULL,
    gift_type TEXT NOT NULL,
    gift_name TEXT NOT NULL,
    gift_data TEXT,
    is_opened INTEGER DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    opened_at DATETIME,
    
    FOREIGN KEY (pet_id) REFERENCES pets(id) ON DELETE CASCADE,
    CHECK (gift_type IN ('file', 'message', 'item')),
    CHECK (is_opened IN (0, 1))
);
```

**字段说明**：
- `pet_id`: 收到礼物的宠物ID
- `from_peer_id`: 发送方节点ID
- `gift_type`: 礼物类型（file=文件, message=消息, item=虚拟物品）
- `gift_name`: 礼物名称
- `gift_data`: 礼物数据（JSON格式或base64编码）
- `is_opened`: 是否已打开
- `created_at`: 收到时间
- `opened_at`: 打开时间

**索引**：
```sql
CREATE INDEX idx_gifts_pet_id ON gifts(pet_id);
CREATE INDEX idx_gifts_is_opened ON gifts(is_opened);
CREATE INDEX idx_gifts_created_at ON gifts(created_at DESC);
```

## 五、索引策略

### 5.1 索引设计原则

1. **查询频率优先**：为高频查询字段建立索引
2. **复合索引**：多字段联合查询使用复合索引
3. **覆盖索引**：尽量让索引包含查询所需的所有字段
4. **避免过度索引**：每个表索引数量控制在5个以内

### 5.2 关键索引

| 表名 | 索引名 | 字段 | 用途 |
|------|--------|------|------|
| pets | idx_pets_is_active | is_active | 查询活跃宠物 |
| pet_states | idx_pet_states_pet_id | pet_id | 唯一索引，快速查找 |
| interactions | idx_interactions_pet_time | pet_id, created_at | 查询宠物互动历史 |
| p2p_connections | idx_p2p_local_pet | local_pet_id | 查询宠物连接记录 |
| file_operations | idx_file_ops_status | status | 查询待处理操作 |

### 6.3 迁移工具

**Rust实现**：

```rust
// src-tauri/src/database/migration.rs
pub struct Migrator {
    conn: Connection,
}

impl Migrator {
    pub fn migrate(&self) -> Result<()> {
        let current_version = self.get_current_version()?;
        let migrations = self.load_migrations()?;
        
        for migration in migrations {
            if migration.version > current_version {
                self.apply_migration(&migration)?;
            }
        }
        
        Ok(())
    }
    
    fn apply_migration(&self, migration: &Migration) -> Result<()> {
        self.conn.execute_batch(&migration.sql)?;
        Ok(())
    }
}
```

## 七、数据备份与恢复

### 7.1 自动备份策略

**备份频率**：
- 每日自动备份（保留最近7天）
- 每周完整备份（保留最近4周）
- 重要操作前手动备份

**备份脚本**：

```rust
pub fn backup_database(db_path: &Path) -> Result<PathBuf> {
    let backup_dir = get_backup_dir();
    let timestamp = chrono::Local::now().format("%Y%m%d_%H%M%S");
    let backup_path = backup_dir.join(format!("main_{}.db", timestamp));
    
    std::fs::copy(db_path, &backup_path)?;
    
    // 清理旧备份
    cleanup_old_backups(&backup_dir, 7)?;
    
    Ok(backup_path)
}
```

### 7.2 数据恢复

```rust
pub fn restore_database(backup_path: &Path, target_path: &Path) -> Result<()> {
    // 1. 验证备份文件
    validate_backup(backup_path)?;
    
    // 2. 备份当前数据库
    let current_backup = backup_database(target_path)?;
    
    // 3. 恢复数据
    std::fs::copy(backup_path, target_path)?;
    
    // 4. 验证恢复结果
    if !validate_database(target_path)? {
        // 恢复失败，回滚
        std::fs::copy(current_backup, target_path)?;
        return Err("恢复失败".into());
    }
    
    Ok(())
}
```

## 八、性能优化

### 8.1 查询优化

**1. 使用EXPLAIN分析查询**：

```sql
EXPLAIN QUERY PLAN
SELECT p.*, ps.mood, ps.energy
FROM pets p
LEFT JOIN pet_states ps ON p.id = ps.pet_id
WHERE p.is_active = 1;
```

**2. 避免SELECT ***：

```sql
-- 不推荐
SELECT * FROM interactions WHERE pet_id = 1;

-- 推荐
SELECT id, interaction_type, content, created_at 
FROM interactions 
WHERE pet_id = 1;
```

### 8.2 写入优化

**1. 批量插入**：

```rust
pub fn batch_insert_interactions(
    conn: &Connection,
    interactions: &[Interaction],
) -> Result<()> {
    let tx = conn.transaction()?;
    
    for interaction in interactions {
        tx.execute(
            "INSERT INTO interactions (pet_id, interaction_type, content) VALUES (?, ?, ?)",
            params![interaction.pet_id, interaction.interaction_type, interaction.content],
        )?;
    }
    
    tx.commit()?;
    Ok(())
}
```

**2. 使用WAL模式**：

```sql
PRAGMA journal_mode = WAL;
```

优势：
- 读写并发性能提升
- 写入速度更快
- 更好的崩溃恢复

### 8.3 定期维护

**1. VACUUM（压缩数据库）**：

```sql
-- 每月执行一次
VACUUM;
```

**2. ANALYZE（更新统计信息）**：

```sql
-- 每周执行一次
ANALYZE;
```

**3. 清理过期数据**：

```sql
-- 删除3个月前的互动记录
DELETE FROM interactions 
WHERE created_at < datetime('now', '-3 months');

-- 删除已打开的礼物（保留1个月）
DELETE FROM gifts 
WHERE is_opened = 1 
AND opened_at < datetime('now', '-1 month');
```

## 九、数据完整性

### 9.1 外键约束

```sql
PRAGMA foreign_keys = ON;
```

确保：
- 删除宠物时自动删除相关状态、互动记录
- 防止插入无效的pet_id

### 9.2 触发器

**自动更新updated_at**：

```sql
CREATE TRIGGER update_pets_timestamp 
AFTER UPDATE ON pets
BEGIN
    UPDATE pets SET updated_at = CURRENT_TIMESTAMP WHERE id = NEW.id;
END;

CREATE TRIGGER update_pet_states_timestamp 
AFTER UPDATE ON pet_states
BEGIN
    UPDATE pet_states SET updated_at = CURRENT_TIMESTAMP WHERE id = NEW.id;
END;
```

**级联更新统计**：

```sql
CREATE TRIGGER update_pet_experience
AFTER INSERT ON interactions
WHEN NEW.interaction_type IN ('chat', 'play')
BEGIN
    UPDATE pets 
    SET experience = experience + 10 
    WHERE id = NEW.pet_id;
END;
```

## 十、安全考虑

### 10.1 SQL注入防护

**使用参数化查询**：

```rust
// ✅ 正确
conn.execute(
    "SELECT * FROM pets WHERE name = ?",
    params![name],
)?;

// ❌ 错误
conn.execute(
    &format!("SELECT * FROM pets WHERE name = '{}'", name),
    [],
)?;
```

### 10.2 敏感数据处理

**不在数据库存储**：
- AI API Key（存储在IndexedDB，加密）
- 用户密码（如果有账户系统，使用bcrypt）

**可存储但需注意**：
- 文件路径（可能暴露用户目录结构）
- P2P节点ID（可能用于追踪）
